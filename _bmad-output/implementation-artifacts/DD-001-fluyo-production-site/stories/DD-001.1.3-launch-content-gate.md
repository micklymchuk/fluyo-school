# DD-001.1.3: Launch Content Gate

**Epic:** 1 - Content integrity  
**Status:** done
**Size:** Medium  
**Depends On:** `DD-001.1.1`  
**Source:** Launch content approval matrix; Architecture AD-4 and AD-8; TS-001 content integrity tests  

## Goal

Prevent mock or unresolved launch-sensitive content from rendering as approved public truth, while still allowing local implementation preview.

## Build Scope

- Add source-status filtering helpers for content records.
- Add a render-mode concept such as `preview` and `production`.
- Add a release/content check script or Nuxt-compatible validation function.
- Add an npm script if a standalone check script is created.
- Document how pages should handle `mock`, `needs_input`, `needs_review`, and `hidden` records.

## Source Status Contract

Allowed statuses:

- `approved`
- `mock`
- `hidden`
- `needs_input`
- `needs_review`

Production behavior:

| Status | Behavior |
| --- | --- |
| `approved` | Render normally. |
| `hidden` | Do not render. |
| `mock` | Do not render publicly; fail required launch gate if required. |
| `needs_input` | Do not render publicly; fail required launch gate if required. |
| `needs_review` | Do not render publicly; fail required launch gate if required. |

## Required Release Gates

- Paid trial price and duration.
- Individual, pair, and mini-group price terms if pricing is visible.
- Teacher profiles and portraits if teacher cards are visible.
- Credentials, proof assets, testimonials, results, and lesson screenshots if proof sections are visible.
- Policy-sensitive FAQ answers.
- Telegram direct fallback.

## Implementation Notes

- Pages may use mock content in local preview, but production mode must hide, block, or fail when required content is not approved.
- Do not silently convert mock testimonials, teachers, prices, or proof into neutral-looking public truth.
- If a section is intentionally hidden, the surrounding layout must remain coherent.
- Keep content gate logic reusable by route stories.

## Acceptance Criteria

### Agent-Verifiable

- [ ] Content helpers distinguish `preview` and `production` render modes.
- [ ] Production mode never renders `sourceStatus: "mock"` records as public claims.
- [ ] Required pricing records block release or hide pricing when not approved.
- [ ] Required teacher/proof/testimonial records block release or hide sections when not approved.
- [ ] Hidden records are omitted without leaving broken empty UI.
- [ ] Content check can be run locally and reports unresolved required records.
- [ ] `npm run build` passes.

### User-Evaluable

- [ ] The implementation makes unresolved launch content visible as a launch risk in source/reports.
- [ ] Public pages do not imply fake proof, fake teachers, fake reviews, or fake prices.

## Verification

- Run `npm run build`.
- Run the content gate command if added.
- Temporarily mark a required price as `mock` in production mode and confirm the gate fails or the section is hidden as designed.
- Temporarily mark optional testimonials `hidden` and confirm the route layout remains coherent.

## Out Of Scope

- Supplying final production prices, teacher assets, proof assets, or testimonials.
- Choosing the final analytics vendor.

## Dev Agent Record

### Implementation Plan

- Add a typed render-mode/source-status helper layer for `preview` and `production`.
- Route launch-sensitive localized adapters through the helper so production consumers receive only approved, non-hidden records.
- Add a standalone content gate command plus a dependency-free verification script following the existing repo test pattern.
- Document route handling for `approved`, `mock`, `needs_input`, `needs_review`, and `hidden` records.
