# DD-001.1.2: Telegram CTA And Tracking Contracts

**Epic:** 1 - Content model, locale, routing, and CTA contracts  
**Status:** Ready  
**Size:** Medium  
**Depends On:** `DD-001.1.1`  
**Source:** Architecture AD-5 and AD-9; DD-001 measurement events; TS-001 analytics tests  

## Goal

Centralize Telegram link creation and analytics event emission so all CTA surfaces preserve context consistently.

## Build Scope

- Add `app/composables/useTelegramCta.ts`.
- Add `app/composables/useTracking.ts`.
- Add shared CTA context and tracking payload types if not already defined in `DD-001.1.1`.
- Integrate the CTA helper into the header CTA shell from `DD-001.0.2`.

## Telegram Requirements

- Base URL is `https://t.me/fluyo_manager`.
- Known path contexts: `exam`, `kids`, `adult`, and generic.
- Known format contexts: individual, pair, mini-group, and generic.
- Helper accepts `path`, `format`, `sourceRoute`, `locale`, and `messageIntent`.
- Prepared messages may be used only when approved or safe for preview.
- Missing context falls back to a generic paid-trial Telegram link.
- URL encoding is handled in one place.
- Rapid repeated clicks must not corrupt link state or tracking payloads.

## Tracking Requirements

Only these event names may be emitted by production components:

- `path_card_click`
- `program_path_view`
- `price_preview_view`
- `pricing_view`
- `teacher_proof_view`
- `telegram_click`
- `telegram_context`

Payloads may include:

- `route`
- `locale`
- `path`
- `format`
- `sourceRoute`
- `messageIntent`

## Implementation Notes

- Use a no-op adapter or console/dev adapter until a concrete analytics vendor is selected.
- Components should call `trackEvent` or an equivalent wrapper rather than vendor APIs.
- Telegram CTA helper should return both the URL and tracking context so CTA components remain thin.

## Acceptance Criteria

### Agent-Verifiable

- [ ] All Telegram URLs are produced by `useTelegramCta`.
- [ ] Header, section, pricing, and final booking CTA surfaces can share one CTA component/helper contract.
- [ ] Unknown or missing context returns a valid generic Telegram URL.
- [ ] Known path contexts produce distinguishable CTA contexts for exam, kids, and adult.
- [ ] Tracking adapter accepts only the seven DD-001 event names.
- [ ] Tracking payloads safely omit or null missing context without throwing.
- [ ] `npm run build` passes.

### User-Evaluable

- [ ] CTA behavior is predictable: every Telegram entry point is clearly a paid-trial contact action.
- [ ] Context preservation helps the manager understand the visitor intent without making the message feel overcomplicated.

## Verification

- Unit-style manual checks in browser console or a small dev page after routes exist:
  - generic CTA
  - `/pricing?path=exam`
  - `/pricing?path=kids`
  - `/pricing?path=adult`
  - repeated CTA clicks
- Confirm no component imports an analytics vendor directly.

## Out Of Scope

- Analytics vendor installation.
- Final prepared Telegram message approval.
- Public launch decision for message text.
