# DD-001.6.1: Available-Pages Production Gating (Page-by-Page Launch)

**Epic:** 6 - Launch scoping
**Status:** review
**Size:** Medium
**Depends On:** `DD-001.5.3` (home design polish) — home is the first page shipping to prod, so it must be in its approved state first
**Source:** User request 2026-07-17 — "for now I like only the home page and want to deploy the site with only it available … without deleting other pages." Follow-ups: (a) "we have no server, deploys on Cloudflare Pages — is that possible?" (b) "flag should be `NUXT_PUBLIC_AVAILABLE_PAGES` not a home-only boolean, because we'll add pages one by one." (c) "if only one page is available there should be no nav menu — only Instagram, language switch and Telegram header actions; the mobile dropdown should not be available either; a single header without nav menu is enough for mobile."

## Goal

Gate which route pages are publicly reachable in production via a **single build-time allowlist**, `NUXT_PUBLIC_AVAILABLE_PAGES`. Pages not on the list redirect to `/` at the Cloudflare edge; they and all their sections, components, content, and verify scripts stay fully intact in the codebase and fully working in local dev. Launching a new page later = add its path to the list and redeploy. No code change, no deletions.

The gate governs three things from the one allowlist:
1. **Edge redirect** — a direct hit to a non-available route (typed URL, bookmark, shared link, crawler) is 302-redirected to `/` at Cloudflare's edge; the page is never served. This also catches any in-page link click to a gated route.
2. **Nav reflects the allowlist** — header nav, mobile nav, and footer nav render links only to available pages. **When home is the only available page, there is no nav menu at all** on desktop or mobile: no desktop nav list, no mobile hamburger/dropdown — just the logo and the header actions (language switch, Instagram, Telegram), shown inline on every breakpoint.
3. **Local dev is unaffected** — with the env var unset (the default), *all* pages are available exactly as today, so the team keeps building the other pages.

## Deployment Reality (why this works with "no server")

Verified from the current build output in `./dist` (the `pages_build_output_dir` from `wrangler.jsonc`):

- The build produces `dist/_worker.js/` — a **Cloudflare Pages edge Function**, a fully managed serverless runtime. There is no server to run or maintain; it is the SSR execution context.
- `dist/_routes.json` is `{"include": ["/*"], "exclude": [<static assets only>]}` — every page route is edge-SSR'd. The pipeline is `nuxt build` (SSR), not `nuxt generate` (static).
- **No page is prerendered to static HTML** — so no static gated file can be served in preference to a redirect; the redirect always applies.

Nitro `routeRules` redirects are emitted into the Cloudflare edge layer and fire before any page render. No Node server, no self-hosted infra.

## Design Decisions

- **D1 — Non-available routes redirect (302) to `/`.** _(Confirmed 2026-07-17.)_ Friendlier than a 404: shared/bookmarked links still land on home and link equity flows there.
- **D2 — Home outbound CTAs to gated routes are left unchanged.** _(Confirmed 2026-07-17.)_ The `/pricing` secondary button in `HomeTrialPricingSection` and the `/programs#…` path cards in `HomePathCardsSection` keep their current markup; in gated mode a click follows the link and is caught by the edge redirect (D1), bouncing to `/`. Home stays byte-identical, all analytics wiring preserved. Nothing in `app/components/sections/home/*` changes.
- **D3 — Allowlist env var `NUXT_PUBLIC_AVAILABLE_PAGES`, resolved BUILD-TIME.** _(Per user: page-by-page launch.)_ Comma-separated list of available page paths, e.g. `"/"`, `"/,/programs"`, `"/,/programs,/teachers,/pricing"`. **Unset ⇒ all pages available** (dev/default behavior). `/` (home) is always forced into the list so home can never be gated by a typo. Resolved once at build in `nuxt.config.ts` and baked into both the redirect `routeRules` and the client/server render — see precondition 3 for why build-time (avoids a hydration mismatch). Toggling for prod = set the var in Cloudflare Pages → Production env and redeploy (git push or dashboard "Retry deployment").
- **D4 — Collapsed header when home is the only available page.** _(Per user.)_ If the allowlist yields no available page other than `/`, render no nav menu: hide the desktop nav list, do **not** render the mobile hamburger/dropdown (`MobileNav`), and surface the header actions (language switch, Instagram, Telegram) inline on all breakpoints so mobile still has them. When ≥1 non-home page is available, current responsive nav behavior is unchanged.

## Critical Preconditions (read before any edit)

1. **One allowlist, one source of truth, resolved once at build.** In `nuxt.config.ts` read `process.env.NUXT_PUBLIC_AVAILABLE_PAGES`, parse to a `string[]`, force-include `/`, and feed the result to **both** `routeRules` (redirects for the complement) and `runtimeConfig.public.pages` (for nav). Components read `useRuntimeConfig().public.pages`; never re-read env in components.
2. **Default must be "all pages".** With `NUXT_PUBLIC_AVAILABLE_PAGES` unset, the resolved list is the full known set → local `npm run dev` and every verify script behave exactly as today. The gate is opt-in and only set for the production deployment.
3. **No hydration mismatch — build-time only.** `runtimeConfig.public` is inlined into the *client* bundle at build. If nav/redirect read a runtime-only env override, the server-rendered nav (env-aware) would disagree with the hydrated client nav (build-time value) → Vue hydration mismatch and links flickering back. Baking one resolved list at build keeps server and client identical.
4. **Avoid the auto-override name collision — store under `public.pages`, NOT `public.availablePages`.** Nuxt would auto-map env `NUXT_PUBLIC_AVAILABLE_PAGES` → `runtimeConfig.public.availablePages` and, at server runtime, overwrite that key with the raw comma-*string* (via `destr`), corrupting the array (`.filter`/`.includes` break on the server, mismatching the baked client array). Storing the parsed array under a differently-named key (`public.pages`) means the auto-override targets a non-existent key and never fires. We read and parse the env var ourselves at build; the human-facing var name stays `NUXT_PUBLIC_AVAILABLE_PAGES` exactly as requested.
5. **Do not delete or move any page, section, component, content record, or verify script.** All routes stay in `app/pages/`. This story only adds gating.
6. **Analytics + copy frozen.** Home CTAs left in place (D2) → `pricing_summary_view`, `path_card_click`, `useTelegramCta` contexts, `useTracking` payloads unchanged. No locale-string edits; gating is structural (config + `v-if`/filter). (See `[[content-gating-policy]]`, `[[production-copy-tone]]`.)
7. **`no_prefix` i18n.** Gated paths are the bare `/programs`, `/teachers`, `/pricing` — no locale segment. Match/redirect on the bare path.
8. **Conditional-render, don't remove markup.** Nav markup must be wrapped in `v-if` / filtered, not deleted, so the static app-shell verify script (`test:app-shell`) that greps for nav structure still passes with the gate off.

## Acceptance Criteria

1. **Allowlist plumbing.** `nuxt.config.ts` parses `NUXT_PUBLIC_AVAILABLE_PAGES` (comma-separated) into a `string[]`, force-includes `/`, and sets both `runtimeConfig.public.pages` and (for every known page not in the list) a redirect `routeRule`. Unset var ⇒ all pages available and the app behaves exactly as today.
2. **Edge redirect (gated).** A production build where a page is not in the allowlist redirects that route (302 → `/`) at the Cloudflare edge without rendering it; `/` and static assets are unaffected. Verifiable via `npm run preview` (wrangler).
3. **Nav reflects allowlist.** Desktop header nav, mobile nav, and footer nav render links only to available pages. No hydration warnings. Gate off ⇒ all links as today.
4. **Collapsed header when only home is available (D4).** With `NUXT_PUBLIC_AVAILABLE_PAGES="/"`: no desktop nav list; no mobile hamburger/dropdown (`MobileNav` not rendered); the language switch, Instagram, and Telegram actions render inline in the header on **both** mobile and desktop; the logo still links to `/`. When ≥1 non-home page is available, the responsive nav (desktop list + mobile hamburger) behaves exactly as today.
5. **Home page untouched.** No `app/components/sections/home/*` file is edited; home is byte-identical. A click on a home CTA targeting a gated route is caught by the edge redirect (AC-2).
6. **No regressions with gate off.** `npm run dev` shows all routes, all links, full responsive nav. All verify scripts pass untouched: `test:home-route`, `test:programs-route`, `test:teachers-route`, `test:pricing-route`, `test:app-shell`, `test:brand-ui`, `test:production-content`, and the rest.
7. **Cloudflare build + reversibility.** `NUXT_PUBLIC_AVAILABLE_PAGES="/" npm run build` completes clean, deploys via `wrangler`, and `npm run preview` demonstrates AC-2/3/4. Adding a path to the list (e.g. `"/,/programs"`) and rebuilding makes that page available and adds its nav link — with no code change.

## Dev Notes

**Stack / deploy reality (verified from `./dist`).** Nuxt 4 + `@nuxtjs/i18n` (`no_prefix`, default `uk`), nitro preset `cloudflare-pages` (edge SSR), `nodejs_compat` on, output dir `./dist`, deployed via `npm run deploy` = `nuxt build` → `wrangler pages deploy`. `dist/_worker.js/` (managed edge function) + `_routes.json` `include: ["/*"]` → every page route is edge-SSR'd; nothing prerendered. `routeRules` redirects apply at the edge with no server to run.

**Routes today (all kept):** `app/pages/index.vue` → `/`; `programs.vue`/`teachers.vue`/`pricing.vue` → gated per allowlist, untouched in dev. `ALL_PAGES` in `app/utils/pages.ts` is the single source for this universe; add a route here when a new page ships.

**Header structure that drives D4** (from `AppHeader.vue` + `MobileNav.vue`): today `.desktop-nav` and `.header-actions` are `hidden … lg:flex` (desktop only), and `MobileNav` (`lg:hidden`) holds the nav links **and** the language/Instagram/Telegram actions inside its hamburger dropdown. So on mobile all actions currently live behind the hamburger. In collapsed mode there is no hamburger, so the actions must move to the inline `.header-actions` shown at all breakpoints — that is the crux of Task 4.

**Files to touch (NEW ×2, UPDATE ×4):**
- NEW `app/utils/pages.ts`; NEW `app/composables/useNavigationLinks.ts`.
- UPDATE `nuxt.config.ts`; `AppHeader.vue`; `MobileNav.vue`; `FooterContactStrip.vue`.

**Do NOT touch:** `app/components/navigation/navigationLinks.ts` (canonical full list), any `app/components/sections/home/*` (D2), any `app/pages/*.vue`, `app/data/*`, locale JSON, `scripts/verify-*.mjs`.

**Reading the list in components.** `const { pages } = useRuntimeConfig().public` then use `useNavigationLinks()`; values are build-time constants → reactive- and hydration-safe.

**Why routeRules for the redirect (not middleware).** Declarative, lives beside the allowlist, emitted at the Cloudflare edge, no client logic. If the pipeline ever switches to `nuxt generate`, routeRules redirects are written to `dist/_redirects` and still enforced at the edge — middleware would not survive that, so prefer routeRules.
