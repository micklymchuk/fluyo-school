# DD-001.4.1: Responsive, Accessibility, And Build Validation

**Epic:** 4 - Responsive, accessibility, analytics, and launch-content verification  
**Status:** Ready  
**Size:** Medium  
**Depends On:** `DD-001.2.1`, `DD-001.2.2`, `DD-001.3.1`, `DD-001.3.2`  
**Source:** TS-001 responsive, accessibility, performance, and build tests  

## Goal

Validate that the four public routes are buildable, direct-loadable, responsive, and accessible enough for DD-001 sign-off.

## Build Scope

- Add focused validation scripts or documented QA procedures for route direct loads and viewport checks.
- Run baseline production build.
- Validate primary keyboard navigation, headings, focus styles, touch targets, and meaningful media alternatives.
- Record validation output in an implementation artifact if automated checks are added.

## Required Routes

- `/`
- `/programs`
- `/teachers`
- `/pricing`

## Required Viewports

- 375x667
- 428x926
- 768x1024
- 1440x900
- 1920x1080

## Accessibility Checks

- One clear `h1` per page.
- Logical heading order.
- Header links, mobile menu trigger, language control, path cards, CTA links, FAQ controls, and footer links reachable by Tab.
- Enter or Space activates button-like controls.
- Focus indicators are visible.
- Mobile menu and FAQ controls expose expanded/collapsed state where applicable.
- Icon-only controls have accessible names.
- Telegram and Instagram links have clear accessible labels.
- Body, button, and link text meet WCAG AA contrast targets.
- Primary touch targets are at least 44px where practical.
- Meaningful media has accurate alt text.

## Responsive Checks

- No horizontal overflow on required viewports.
- Header and mobile nav remain usable.
- Hero, path cards, proof, pricing, teachers, lesson proof, FAQ, and CTA sections do not overlap.
- Text inside buttons, cards, tabs, labels, and pricing blocks wraps cleanly.
- Images and proof assets reserve stable dimensions or aspect ratios.

## Acceptance Criteria

### Agent-Verifiable

- [ ] `npm run build` passes.
- [ ] `/`, `/programs`, `/teachers`, and `/pricing` load directly.
- [ ] No uncaught console errors, hydration errors, or page errors occur during initial load and core interactions.
- [ ] Required viewports have no horizontal overflow.
- [ ] Primary navigation and CTA controls are keyboard reachable.
- [ ] FAQ accordions are keyboard reachable and expose state.
- [ ] Each page has one clear `h1`.
- [ ] Focus indicators are visible on light and dark sections.
- [ ] Rendered media has stable dimensions and accurate alt text.

### User-Evaluable

- [ ] Mobile, tablet, laptop, and wide desktop layouts feel intentionally designed.
- [ ] Text is readable and not cramped in Ukrainian or English.
- [ ] Visual hierarchy still matches the layout schema.

## Verification

- Run `npm run build`.
- Use browser or Playwright checks across all required routes and viewports.
- Compare screenshots against `_bmad-output/planning-artifacts/fluyo-school-page-layout-schemas.html`.
- Confirm no accidental one-page prototype rebuild and no separate audience routes.

## Out Of Scope

- Final content owner approval.
- Designer sign-off.
- Analytics payload validation beyond basic console/runtime health.
