4. Three filled burgundy primaries compete down the page (hero, speaking club, trial pricing).
5. Speaking Club is a headline, a small sticker, one sentence, and a button floating in cream — no structure.
6. The diamond pattern hard-cuts mid-diamond into the solid burgundy reviews band (visible triangle seam).

8. `FooterContactStrip.vue:77` is `bg-surface` (white) — the only white field on the page; desktop and mobile footers end differently.
9. `UiWatermark` scatters six glyphs at varied sizes that collide with card edges (path cards, pricing) and look accidental.

## Component Architecture (SOLID)

Every distinct visual unit this story introduces or reshapes gets its own component. The project rules already encode the dependency direction (project-context.md: repeated units are presentational components with typed props and emitted events, no i18n/content/tracking imports inside; sections resolve `t()`, contexts, and analytics). Apply them through this lens:

- **SRP** — one visual responsibility per component. Sections compose and wire; primitives render. A section template that inlines a reusable visual unit's markup is a violation.
- **OCP** — extend existing primitives through props/variants instead of copying their styles into a new place. Poster-scale type is a new size variant on `UiLockupHeading`, not a parallel heading component.
- **LSP** — every variant of a primitive must be a drop-in: `inverse`, `size`, and `mode` props change appearance only, never the slot/emit contract.
- **ISP** — small, focused prop interfaces (resolved strings, flags, URLs). No config-object props, no props a variant ignores.
- **DIP** — sections depend on primitive contracts (props/slots/events); primitives never reach upward into composables, content records, or route state.
