# DD-001.5.1: Brand UI Components From Design System

**Epic:** 5 - Brand design system adoption  
**Status:** done  
**Size:** Large  
**Depends On:** `DD-001.3.3` (route/section architecture), brand tokens already applied in `app/assets/css/tailwind.css`  
**Source:** `_bmad-output/design-system/fluyo-brand-design-system.md` (authoritative spec, sampled from `public/design-insta/` references); visual style tile `_bmad-output/design-system/fluyo-brand-design-system.html`

## Goal

Make the site render the Fluyo brand, not just its colors: load the brand typefaces and build/restyle the UI components that carry the brand's signature moves — pill controls, script+sans lockup headings, eyebrow pills, the thick-frame hero container, the postage-stamp testimonial card, the underline vocabulary list, and the F-monogram watermark texture — all consuming the tokens already present in `app/assets/css/tailwind.css`.

## Decision Record

- **Supersedes "square geometry":** the DD-001 global AC "square geometry, hairline borders, restrained palette" predates the brand extraction. The brand mandates pill controls and `--radius-card: 1.25rem` cards. This story deliberately retires square geometry; hairline borders, restrained palette, and no-decorative-shadows remain in force. Record this in the design log when done.
- **Brand tokens are already live** (applied 2026-07-14): cream page `#faf5f2`, burgundy `#7a1e2b`/`#5e1420`, rose, blush, warm ink text, `--font-script`, `--tracking-display`, `--radius-card`, `--radius-pill`. Do not re-derive values; consume tokens only.
- **Watermark "blush-on-cream" is implemented as burgundy at 6% opacity** (review decision 2026-07-14): the blush token at the mandated ≤6% opacity is imperceptible; burgundy at 6% renders the intended blush tint. The Objects table's "blush-on-cream" wording describes the visual result, not the token.
- **Inverse-band CTA treatments** (review decision 2026-07-14): on the burgundy band, primary buttons flip to cream fill with burgundy text and secondary buttons to cream border/text — burgundy-on-burgundy is invisible. Applied via `.section--inverse :deep()` in `UiSection`, no button API change.

## Implementation Notes

### Fonts (Task 1 — everything else depends on it)

- Self-host woff2 files under `public/fonts/`; declare `@font-face` in `app/assets/scss/main.scss` (authored global styles belong there). No `@nuxt/fonts` or other new dependency without a separate decision — Cloudflare Pages serves `public/` statically, which is all we need.
- **Inter**: `latin` + `cyrillic` subsets, weights 400/500/600/700 (or the variable font if smaller than four statics). Ukrainian copy renders in it — cyrillic subset is non-negotiable.
- **Pinyon Script**: `latin` subset only (~28 KB woff2). The brand rule is script-sets-Latin-only; never feed it Cyrillic content (glyphs are missing — fallback would silently mix faces).
- All `@font-face` use `font-display: swap`. Tokens already reference the families — `--font-body`/`--font-display` (Inter) and `--font-script` (Pinyon) — so loading the files completes the chain; do not rename families.
- Keep stable type sizes: no viewport-width scaling (`clamp()` with `vw`, `vmin`, etc.) on any font-size — global AC. Use per-breakpoint sizes if a heading must shrink on mobile.

### Component rules (project-context.md is binding)

- Scoped styles: every component `<style scoped>` block that uses `@apply` MUST start with `@reference "~/assets/css/tailwind.css";` — Tailwind v4 scoped styles fail the build without it (learned in DD-001.0.2).
- Named component-local classes in templates (`.stamp-card`, `.lockup-script`), styles via `@apply` with token-backed utilities. No raw hex anywhere in component CSS; if a needed utility is missing, add a token to `@theme` in `app/assets/css/tailwind.css` first.
- UI primitives stay presentational and route-agnostic: typed props for labels/variants, slots for content, no i18n/content/tracking imports.
- Explicit SFC imports where components nest (auto-import gaps hit DD-001.0.2 in layouts/navigation).
- Interactive controls keep ≥44px practical hit area (pill height must not shrink buttons below it).
- New type tokens (e.g. `--text-lockup-script`, `--text-lockup-caps`) belong in `@theme`, not hard-coded sizes.

### Brand-specific gotchas (learned while building the style tile)

- **Script font metrics:** Pinyon Script has oversized ascenders/descenders. Any pill/badge containing it must use a fixed height with flex centering plus a small optical baseline nudge (~0.12em up) — padding-driven sizing renders visibly taller than sibling sans pills.
- **Stamp mask recipe** (verified rendering): two mask layers — `linear-gradient(#000 0 0)` inset by half the perforation pitch covering the interior, plus `radial-gradient(hole, transparent 98%, black) round` sized to the pitch for the edge holes. Include `-webkit-mask` twin. Wrap in `@supports (mask-repeat: round)` (or equivalent) so unsupported browsers get a plain rounded card, never a solid-rectangle glitch.
- **Contrast law:** burgundy⇄cream both directions are AAA. `rose` and `blush` are decorative-only — never text on either ground.
- **Watermark and stamp edges are decoration:** `aria-hidden="true"`, no reading-order impact, `pointer-events: none` on watermark.
- Existing hover/motion transitions already respect `prefers-reduced-motion` via `main.scss`; keep new transitions on the shared duration/ease tokens so that guard keeps applying.

### Verification script pattern

Follow `scripts/verify-ui-primitives-and-app-shell.mjs`: dependency-free Node, string/regex assertions against source files, wired as `"test:brand-ui": "node scripts/verify-brand-ui-components.mjs"`. Assert at minimum: font files exist under `public/fonts/`, `@font-face` declarations present with `font-display: swap`, Pinyon declaration has no cyrillic unicode-range, each new component file exists with `@reference` header, `UiButton` uses `rounded-pill`, `UiCard` uses `rounded-card`, no raw hex values in new component styles, `UiWatermark` template contains `aria-hidden`.

- `UiWatermark` uses a fixed deterministic glyph scatter (no randomness — SSR/client renders must match), burgundy at 0.06 opacity on cream, cream on inverse.

### Debug Log

- Initial 375px headless-Chrome screenshots showed uniform right-edge clipping on every route; suspected horizontal overflow. Root cause: headless Chrome clamps the window to a ~500px minimum and crops `--screenshot` to the requested width. Re-verified with CDP `Emulation.setDeviceMetricsOverride`: `scrollWidth === innerWidth` (no overflow) on all 4 routes × 375/768/1440.
- CDP metrics confirmed: Inter regular+bold load on all routes; every visible `.ui-button` ≥44px tall with 9999px radius; section titles uppercase/700/1.92px tracking; eyebrow pills burgundy. Pinyon reported unloaded on routes only because no route composes script components yet (adoption is DD-001.5.2) — force-loading via `document.fonts.load` + a token-driven probe string rendered correct Pinyon glyphs.
- Keyboard Tab testing (real `Input.dispatchKeyEvent`) exposed that the global teal focus ring (`#176f8f`) is ~1.75:1 against the burgundy inverse band — near-invisible. Fixed with `.section--inverse :deep(:focus-visible) { outline-text-inverse }` (~9.5:1). Odd mid-transition outline colors in the first probe were the `transition-colors` utility animating `outline-color` for 160ms — cosmetic, left as is.
