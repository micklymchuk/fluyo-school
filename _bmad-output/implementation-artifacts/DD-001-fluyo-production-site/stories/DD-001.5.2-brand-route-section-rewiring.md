## Goal

Compose the DD-001.5.1 brand components into all four routes and run a per-section typography and spacing pass: every section uses token-backed type sizes and colors (no arbitrary values), brand heading treatments, and the brand's unhurried spacing rhythm — without changing any copy, route, analytics event, or CTA contract.

## Critical Preconditions (read before any edit)

1. **Read the implemented 5.1 components first** — `app/components/ui/UiEyebrowPill.vue`, `UiLockupHeading.vue`, `UiFrameBox.vue`, `UiStampCard.vue`, `UiUnderlineList.vue`, `UiWatermark.vue` — and the 5.1 story's Completion Notes. Their final props/slots are the contract; do not code against the 5.1 spec table if the implementation drifted.
2. **Script is Latin-only.** Ukrainian copy NEVER renders in Pinyon. In lockup headings the script line may only carry existing Latin brand words (e.g. "Fluyo", "speaking club" accents already present in content); Ukrainian headlines stay in the tracked display sans. Copy changes are out of scope — if no Latin word exists in a heading, use the caps-only treatment, do not invent copy.
3. **Verify scripts are load-bearing.** `verify-programs-route.mjs`, `verify-teachers-route.mjs`, `verify-pricing-route.mjs` hard-assert: section root class names (`{page}-page__{section}`, `trust-note`), data attributes (`data-program-path`, `data-proof-surface="…"`, `data-pricing-format`), component tags, event bindings (`@pricing-click`, `@cta-click`), exact `defineProps<{…}>` shapes (order- and whitespace-locked), and two style values (`scroll-mt-` programs L213, `aspect-` teachers L240). Cheapest path: **preserve root classes, data attributes, emits, and prop shapes**; restyle inside. Where a markup change is genuinely required, update the assertion in the same commit and say so in the Dev Agent Record. `verify-home-route.mjs` additionally requires path cards to contain `NuxtLink` (L203) and the exact `t(\`…\`)` literals (L217, L227-229) — keep those intact.
4. **Analytics are frozen.** IntersectionObserver surfaces, `useSurfaceViewObserver` wiring, event names, and Telegram context payloads must be byte-for-byte preserved. This story is visual only.

## Typography And Color Pass (site-wide rules)

- **No arbitrary type sizes anywhere**: add `--text-card-title: 1.35rem` (+ line-height companion) to `@theme` and replace all four `text-[1.35rem]`. After this story, `grep -rn 'text-\[' app/` must return nothing.
- Headings: `section-title` treatment (display sans, bold, uppercase, `tracking-display`) comes from `UiSection` — sections with custom heading markup (HomeHero, ProgramPathPanel, TeachersProofColumns) must match it or use `UiLockupHeading`; no third heading style may exist.
- Colors on inverse bands: text uses `text-text-inverse` tokens only; `rose`/`blush` never carry text (decorative only); links/CTAs on burgundy use cream treatments.
- No viewport-width font scaling (global AC) — per-breakpoint sizes only.

## Spacing Pass (site-wide rules)

- Replace every raw spacing utility flagged in the map (`gap-1`, `px-2 py-1`, `px-4`, `mr-1`, `mb-1`, `min-h-11`, `w-20`, `max-w-72`, `min-h-72`, `min-h-[calc(86svh-4rem)]`) with token-backed utilities; add at most 2–3 new `@theme` spacing tokens if a needed step is missing (e.g. `--spacing-chip-y/x`) — do not grow the scale ad hoc.
- Section rhythm per design system: header/hero sections `spacious`, dense proof/list sections `default` or `compact`; consecutive same-background sections must not double-pad (check adjacent pairs on every route at 375 px).
- Content never touches edges: keep `px-page-gutter` intact everywhere; frame/stamp components bring their own internal padding — remove now-redundant wrappers instead of stacking padding.

## Execution Model — Phased With Home Review Gate

This story is implemented **route by route, Home first, with a mandatory user review checkpoint after Home** before any other route is touched.

- **Home is the precedent-setter.** Every site-wide decision (proof-item treatment, lockup usage, frame weight, chip style, spacing rhythm) is made while implementing Home and applied there first. The Home checkpoint is where the user approves those precedents — later routes only replicate approved decisions, never introduce new treatments.
- **Shared/global pieces are built in the phase that first needs them** (new tokens, small shared styling helpers, verify-script assertion updates) — not batched upfront. If a later route requires adjusting a shared component, make the change in that phase and re-run the verify scripts of all previously completed routes in the same phase.
- **At the Home checkpoint the dev agent MUST STOP:** present screenshots of `/` at 375/768/1440, the list of precedent decisions made (one-line rationale each), and any verify-script assertions changed. Set story status to `awaiting-home-review` and wait for explicit user approval. Silence is not approval — do not touch Programs until the user answers.
- After approval, implement Programs → Teachers → Pricing in order, applying the approved precedents. Post a short screenshot report after each route so the user can interject; no additional hard stop unless the user asks for one.
- If the user requests changes at the Home review, apply them on Home, update the precedent list, and only then continue.
