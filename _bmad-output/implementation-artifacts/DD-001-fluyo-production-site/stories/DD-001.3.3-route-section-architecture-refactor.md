# DD-001.3.3: Route Section Architecture Refactor (/programs, /teachers)

**Epic:** 3 - Teachers & Proof and Trial & Pricing implementation (architecture retrofit; also covers Epic 2's `/programs`)  
**Status:** done  
**Size:** Medium  
**Depends On:** `DD-001.2.2`, `DD-001.3.1`, `DD-001.3.2`  
**Routes:** `/programs`, `/teachers`  
**Source:** Component architecture rules in `_bmad-output/project-context.md` (Framework-Specific Rules); reference implementations `app/pages/index.vue` and `app/pages/pricing.vue`

## Goal

Refactor the two remaining monolithic route pages — `app/pages/programs.vue` (337 lines) and `app/pages/teachers.vue` (407 lines) — into the thin-composer section-component architecture already used by `/` and `/pricing`, with **zero visual or behavioral change**: rendered DOM (classes, ids, aria attributes, data attributes), tracking event names and payloads, and Telegram CTA URLs must stay byte-identical.

## Architecture Rules Being Enforced (from project-context.md)

1. **Thin composer pages:** a page under `app/pages/` holds only SEO registration, route-level tracking, and an ordered list of section components. No `UiSection`, no `v-for`, no copy resolution in the page.
2. **One component per visual section** under `app/components/sections/` named `<Route><Section>Section.vue`.
3. **Presentational leaf components** for repeated `v-for` units, under a domain folder (`app/components/programs/`, `app/components/teachers/`): configured entirely by the parent through typed props carrying resolved strings/flags/URLs, emitting events instead of tracking, with **no** `useI18n`, `~/data/content`, `useTracking`, `useTelegramCta`/`resolveTelegramCta`, or business-logic composable imports inside — only markup, styles, and aria. Reference shapes: `PricingFormatCard.vue`, `PricingFaqItem.vue`.
4. **Shared cross-section/cross-page state or behavior lives in composables**, not in pages or duplicated across sections.

## Target Structure

### Shared composable (NEW)

`app/composables/useSurfaceViewObserver.ts` — both pages currently duplicate an identical IntersectionObserver block (`onMounted`/`onBeforeUnmount`, `rootMargin: '0px 0px -35% 0px'`, `threshold: [0.05, 0.1, 0.15, 0.2, 0.25]`, the `visibleEnough` rule of `intersectionRatio >= 0.25 || intersectionRect.height >= rootBounds.height * 0.5`, once-per-surface dedupe, SSR/`IntersectionObserver`-undefined guards). Extract it once: the composable accepts a data-attribute name (e.g. `data-program-path`, `data-proof-surface`) and a callback receiving the attribute value of a sufficiently visible element; it owns observer setup, dedupe, and disconnect. Observation thresholds and the visibility rule must be preserved exactly — the runtime `observe`-trigger tracking events depend on them.

| --- | --- |

`teacher_proof_view` state note: the once-per-surface dedupe set does not need to be shared across sections — surfaces do not overlap between sections (`teacher-cards`/`credentials-proof`/`lesson-proof` belong to the proof-columns section, `testimonials` to the testimonials section, `trust-cta` is activate-only in the CTA strip). Each section tracks its own surfaces independently; the event payload shape (`route`, `locale`, `sourceRoute: 'teachers'`, `surface`, `trigger`) must stay identical.

Presentational leaves under `app/components/teachers/`:

- `TeacherCard.vue` — props: `id`, `initials`, `name`, `role`, `bio`, `fitLabel`, `fitItems: string[]`, `credentials: string[]`.
- `TeacherProofItem.vue` — props: `kindLabel`, `title`, `caption` (reused by credentials, lesson-proof, and testimonials sections — one component, three usages).
- `TeacherCredentialStripItem.vue` — props: `owner`, `facts`.
- `TeacherTestimonial.vue` — props: `quote`, `sourceLabel`.

Scoped styles move with their markup: each extracted component carries the `@apply`-based classes for the DOM it renders (same pattern as the pricing split — class names and their CSS must not change).

## Implementation Notes

- **This is a pure refactor.** No copy, content-record, locale-file, or type changes are expected. `pages.programs.*`, `pages.teachers.*`, `programsSections.*`, `teachersSections.*` i18n keys stay as-is. If a change to `uk.json`/`en.json` or `app/data/content/` seems necessary, stop — the decomposition is wrong.
- **Contracts that must not change:** `CtaSourceRoute` union (regex-pinned by `test:telegram-cta`), tracking event names (`program_path_view`, `teacher_proof_view`, `telegram_context`, `telegram_click`) and payload fields, `/pricing?path=${path.id}` links from program panels (consumed by `usePricingPathContext`), anchor ids (`:id="path.anchorId"`).
- **Verifier scripts are the tests — red first.** `scripts/verify-programs-route.mjs` and `scripts/verify-teachers-route.mjs` currently assert monolithic-page patterns (e.g. programs page must contain `useI18n()`, `learningPaths`, `priceHintIds`, `IntersectionObserver`). Rewrite their page/section assertions to demand the composed structure *before* refactoring, confirm they fail against the current pages, then refactor to green. Follow `scripts/verify-pricing-route.mjs` as the template: page must render ordered `<Route*Section` components and must not include `<UiSection` or `v-for`; sections own the business-logic patterns; leaf components get exact `defineProps<{...}>` contracts, a `defineEmits` requirement, and negative checks (`useI18n`, `from '~/data/content'`, `resolveTelegramCta`, `useTracking` forbidden). Keep the existing locale-shape and shared-contract checks untouched.
- **Cyrillic guard** applies to every new component file (no hard-coded Ukrainian copy); presentational leaves are excluded from the `useI18n()` requirement but still checked for Cyrillic — same as `PricingFaqItem` handling in the pricing verifier.
- No new dependencies. No test runner exists; verification is the `scripts/verify-*.mjs` suite plus `npm run build` plus a Playwright runtime audit (import chromium from the npx cache absolute path, as in previous stories — `NODE_PATH` does not work with ESM).
- The dev server logs tracking events to the console (`[tracking]` prefix) — the runtime audit captures payloads from there.
