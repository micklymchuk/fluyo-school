# DD-001.1.1: Typed Content, Locale, Asset Metadata, And SEO

**Epic:** 1 - Content model, locale, routing, and CTA contracts  
**Status:** done  
**Size:** Large  
**Depends On:** `DD-001.0.1`  
**Source:** Architecture AD-3, AD-8, AD-11; DD-001 data models; launch-content matrix  

## Goal

Create the typed bilingual content layer that all pages and sections consume, with Ukrainian as the default locale and English as an equivalent structure.

## Build Scope

- Add `app/data/site-content.ts`.
- Add `app/data/asset-manifest.ts`.
- Add `app/composables/useLocale.ts`.
- Add `app/composables/useSeo.ts` or equivalent SEO helper.
- Define reusable TypeScript types for localized strings, route content, launch-sensitive source status, learning paths, pricing, teachers, proof, testimonials, FAQ, and CTA intents.

## Data Models

| Model | Required Fields |
| --- | --- |
| `PageContent` | route id, path, localized SEO metadata, section order, localized page intro text |
| `LearningPath` | id `exam`/`kids`/`adult`, anchor id, localized title, proof cues, price hint ids, CTA intent |
| `PriceItem` | id, format, localized label, localized value/caption, source status, required-for-launch flag |
| `TeacherProfile` | id, localized name/role/bio, audience fit, portrait asset id, credentials, source status |
| `ProofAsset` | id, kind, localized title/caption/alt, approval status, privacy status, usage context |
| `Testimonial` | id, localized quote/source label, audience, permission/source status |
| `FaqItem` | id, localized question/answer, policy sensitivity, source status |
| `CtaIntent` | path, format, sourceRoute, locale, messageIntent |

## Locale Requirements

- Supported locale codes: `uk`, `en`.
- Ukrainian is default and does not require a URL query.
- English uses `lang=en` until locale-prefixed routes are intentionally adopted.
- Unsupported locale state falls back to Ukrainian.
- Localized content must keep matching structure for `uk` and `en`.

## SEO Requirements

- Each route has localized title and description.
- Page components call one helper rather than duplicating metadata logic.
- SEO follows the active locale and pricing path context where useful.

## Content Rules

- Mock launch content may be included for local preview, but every launch-sensitive record must include source status.
- Allowed statuses: `approved`, `mock`, `hidden`, `needs_input`, `needs_review`.
- Mock teacher, proof, testimonial, result, pricing, and policy-sensitive FAQ values must be traceable as mock or unresolved.
- Keep route copy out of UI primitives.
