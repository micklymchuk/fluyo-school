- (assumption) Fast path deliverable scope: architecture spine only unless the user later asks for a deck or fuller solution design.
- (constraint) Brownfield reality: repo is a Nuxt 4 ESM app with app/app.vue still on NuxtWelcome, npm lockfile, Cloudflare Pages/Nitro config, no test runner, and no standalone design-system package.
- (constraint) Planning source of truth: production IA is four pages /, /programs, /teachers, /pricing; do not rebuild an 11-section single landing page and do not split exam/kids/adults into separate routes for v1.
- (constraint) Product conversion engine is paid trial booking through Telegram with path-aware context; Ukrainian is default and English is secondary.
- (constraint) Mock teachers, testimonials, prices, results, screenshots, and trial duration are implementation-preview content only and must not be represented as approved public launch truth.
- (version) Verified stack on 2026-07-08: npm registry latests are nuxt 4.4.8, vue 3.5.39, vue-router 5.1.0, wrangler 4.108.0, @types/node 26.1.1, nitro-cloudflare-dev 0.2.2; local lockfile installs nuxt 4.4.8, vue 3.5.39, vue-router 5.1.0, wrangler 4.105.0, @types/node 26.0.1, nitro-cloudflare-dev 0.2.2.
- (decision) Use a layered Nuxt frontend architecture: pages compose sections; sections consume typed content, UI primitives, and composables; UI primitives consume only CSS tokens; platform/Nitro code is isolated. This binds all source modules and prevents route-local mini-architectures.
- (decision) Freeze the v1 production route set as /, /programs, /teachers, /pricing, with path context handled by anchors/query/context helpers. This binds IA and prevents route sprawl or a single-page rebuild.
- (decision) Keep bilingual public copy in one typed content module with matching uk/en shapes, uk default, and route/page content composed from the same source. This binds localization and prevents hard-coded divergent copy.
- (decision) Keep commercial terms and proof assets in typed content records with source status mock or approved; public launch must hide or fail on mock-only proof/pricing. This binds content integrity and prevents fake-proof leakage.
- (decision) Centralize Telegram CTA generation and conversion event payloads in composables/utilities; components pass path or format context instead of constructing t.me links. This binds booking behavior and prevents inconsistent inquiries.
- (decision) Use URL/query-derived context and small component-local state only; do not add a global store for v1. This binds state mutation and prevents duplicated language/path/booking state.
- (decision) Implement a minimal in-code UI foundation: CSS custom-property tokens plus local UI primitives and section components inside app/, not a standalone WDS design system. This binds UI reuse and prevents design-system overhead.
- (decision) Assets require metadata for alt text, approval status, privacy safety, and usage context before rendering as proof. This binds media handling and prevents privacy or authenticity drift.
- (decision) Measurement event names are fixed by the UX source and emitted through one analytics adapter; vendor choice is deferred. This binds analytics semantics and prevents event-name drift.
- (decision) Cloudflare Pages with Nuxt Nitro cloudflare-pages preset is the production boundary; build output stays dist and environment/runtime settings stay aligned between nuxt.config.ts and wrangler.jsonc. This binds operations and prevents split hosting assumptions.
- (question) Open before public launch: exact prices, trial duration, approved teacher/proof/testimonial assets, prepared Telegram messages per path, and analytics vendor.
- (direction) Defer CMS/admin, payments/scheduling, auth, Nuxt i18n module, and standalone design system until content cadence, localization routing, or reuse pressure proves they are needed.
- (decision) Locale selection is query-based for English in v1: Ukrainian omits query and English uses lang=en until locale-prefixed routes are adopted. This prevents incompatible switcher implementations.
- (decision) Localized SEO metadata is owned by the same page content records as visible copy and consumed through one helper. This prevents stale single-language metadata.
- (decision) Preview and reference assets stay outside public assets by default; public/assets/proof is only for approved public proof. This prevents accidental deployment of mock media.
- (event) reviewer gate passed after applied fixes for asset-public boundary, locale query convention, and localized SEO metadata ownership.
